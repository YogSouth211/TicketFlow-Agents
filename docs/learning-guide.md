# TicketFlow Agents 学习指南与面试准备

先看业务流程，再追代码。每一步只回答一个问题，不需要逐行背代码。

## 一句话介绍

TicketFlow Agents 是本地 SaaS 客服演示工作台：Supervisor 把问题交给产品知识、问题排查或工单处理智能体；智能体通过限定工具读取知识与账号工单数据，工单工作台负责人工跟进。

## 先画出这条线

```text
用户输入 → Gradio 页面 → LangGraph Supervisor
                        ├─ 产品知识 Agent → SQLite 知识条目
                        ├─ 问题排查 Agent → 账号与相似历史工单
                        └─ 工单处理 Agent → 创建工单 / 查询状态
                    → Supervisor 汇总 → 页面回答
人工处理 → 工单工作台 → SQLite 状态与处理记录
```

三个专职 Agent 都用同一个 Qwen 模型，但拥有不同的提示词和工具权限。它们不是三个独立服务。对话上下文保存在 `MemorySaver`，仅当前服务进程有效；右侧“执行历史”单独存在当前 Gradio 页面状态中；工单、处理记录和知识条目写入 SQLite，重启后仍在。

## 五步熟悉项目

### 第 1 步：只看页面和一轮完整业务

打开“智能协作”，先问“如何邀请同事加入工作区？”，再问“帮我排查 acme-001 的报表导出失败”。接着要求创建工单，回复“确认创建”，到“工单工作台”刷新并更新状态，最后按工单号询问状态。对照右侧按轮展示的执行历史，记下每次由哪个 Agent 处理、调用了什么工具、读写了什么数据。模型路由并非每次都相同，以实际记录为准。

### 第 2 步：看请求从哪里进入

读 `app.py` 和 `src/ui/app.py` 的 `create_app`、`show_user_message`、`generate_response`、`_record_trace`。只追四件事：页面如何接收输入、如何生成 `thread_id`、如何调用 `_graph.stream`、如何从完整消息历史中取出本轮新增调用并按轮显示。暂时跳过 CSS。

### 第 3 步：看为什么会选不同 Agent

读 `src/agents/graph.py` 和 `src/agents/prompts.py`。指出 Supervisor、三个 ReAct Agent 各自的职责和工具。试着解释：产品问题为什么不能直接交给工单 Agent？“先排查再建单”的请求会发生什么？

### 第 4 步：看工具和数据库边界

读 `src/tools/product_knowledge.py`、`triage.py`、`ticketing.py`，再读 `src/db/database.py`、`support_data.py`。画出四张表：`accounts`、`support_tickets`、`ticket_events`、`knowledge_articles`。重点理解创建工单的账号与描述校验、参数化 SQL、状态更新记录，以及知识停用后不再参与检索。

### 第 5 步：自己做一次小修改

在“知识库”加一条你自己写的产品指南和关键词，再向产品知识 Agent 提问。然后在 `src/agents/prompts.py` 中调整一句路由提示词，预测它会如何影响分工。每次只改一处并观察行为，不需要先读完全部源码。

## 面试常见追问：用自己的话回答

1. **为什么叫多智能体？** Supervisor 协调三个职责、提示词和工具都不同的 ReAct Agent；它们共享同一模型 API，不是三个独立模型或微服务。
2. **Supervisor 做什么？** 根据用户意图选择专职 Agent；复杂请求可以依次交给多个 Agent，最后汇总结果。
3. **工具调用和普通聊天有什么差别？** 模型决定调用工具及参数，工具执行实际的 SQLite 查询或写入，模型再根据结果回复；工单不是模型“说创建了”就算创建。页面会核对建单工具返回的工单号。
4. **如何避免错误建单？** 页面先要求“确认创建”，Agent 专用建单工具读取服务端确认状态，未确认就拒绝写库；底层工具还校验账号、描述长度和优先级。演示账号 ID 不是真实身份认证。
5. **如何保存多轮对话？** LangGraph 的 `MemorySaver` 用 `thread_id` 区分会话，进程重启即丢失；右侧执行历史另存在当前页面的 Gradio 状态，刷新或新建对话会清空；工单和知识是 SQLite 持久化数据。
6. **知识库是不是 RAG？** 这里是小型 SQLite 关键词检索，没有向量化；向量与 BM25 混合检索在 DocFusion RAG 项目中实现。
7. **相似工单怎么找？** 对中文取连续双字、英文取词，补少量中英同义词，按词项命中数排序。它只是排查线索，不代表问题原因已确定。
8. **项目目前最大的限制？** 本机演示，无真实登录、权限、通知；关键词检索简单，MemorySaver 不跨进程持久化。6 条路由样例的一次运行仅通过 4 条，模型路由仍不稳定。
9. **为什么执行历史不会把旧工具调用算到新 Agent 名下？** `full_history` 会在每次节点更新中带回之前的消息。页面用当前请求的 HumanMessage 定位本轮起点，再按消息 ID 去重，只记录本轮新出现的工具消息；展示时把各轮记录分别保存。

## 面试前的自检

不看代码，能在 60 秒内画出上面的流程；能指出一条创建工单请求最终写入了哪两张表；能解释为什么对话重启会丢、工单不会丢。答不上来时，回到对应一步操作和文件，不必背框架全部 API。
